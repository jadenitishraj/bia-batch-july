01

Classical ML vs Deep Learning vs Gen AI

These three are not fighting each other. They sit on top of each other. Each new one does more of the work, so the human does less.

The one-line version

  • Classical ML — you tell the computer what to look at. It learns the rule.
  • Deep learning — the computer works out what to look at, by itself. You just hand it the raw photo, sound or text.
  • Gen AI — the computer learns what the data looks like, so it can make new things. Not just sort old things.
Artificial Intelligence
Machine Learning
Deep Learning
Generative AI
LLMs · diffusion models · speech and music models
Each one sits inside the bigger one. Nothing got thrown away

One problem, three ways

Same job — catching spam email. Watch the work slowly move from the human to the machine.

Classical ML
A person writes code to count the "!" marks, count the links, check who sent it. Those numbers go into a simple model. The person decides what matters.
Deep learning
Just give it the plain email text. It figures out by itself that "free" sitting next to "click" is a bad sign. The machine decides what matters.
Gen AI
Just ask it: "Is this spam, and why?" It replies in normal English. It never even saw your spam data. The machine writes the answer.

The one big difference: sorting vs making

Classical ML and most deep learning are sorters. They draw a line between groups. You give them something, they give back a label. Cat or dog. Fraud or clean. Spam or not.

Makers learn what the data itself looks like. So you can ask them to make a new one. That is the whole difference.

Put it simply: a spam sorter can never write you an email. A maker can.

The trap everyone falls into

Gen AI did not kill classical ML. If your data is a table with 40 columns and you want to predict one thing, a simple old model beats an LLM. It is more accurate, cheaper and faster. Every time.

Most AI running inside banks today is still this old kind. Use Gen AI when the input is messy text or images and the question has no fixed answer list. Not before.

How to choose

A table, with one column you want to predict → classical ML.

Photos or sound, and you want one fixed answer → deep learning.

Text goes in, text comes out, and the answer could be anything → Gen AI.

A bank has 5 years of loan data — 60 numeric columns, one default/no-default label. What should you build first?
Gradient boosting. A neat table with a clear yes/no column is exactly what classical ML is for. It trains in minutes, costs almost nothing to run, and you can show the bank inspector why it said no.

Let us actually do the maths

Take the simplest one: linear regression, predicting a house price.

price = w₁ × size + w₂ × bedrooms + b
That is the entire model. Three numbers to learn
  • w₁ and w₂ are weights. How much each thing matters. If size matters a lot, w₁ is big.
  • b is the bias. The starting price before anything else is counted.
  • Training just means: find the values of w₁, w₂ and b that make the predictions closest to the real prices.

How does it know if it is close? It measures the mistake:

error = average of (real price − predicted price)²
Square it so that being too high and being too low both count as bad

Then it nudges w₁, w₂ and b again and again, each time making that error a bit smaller. That nudging is called gradient descent. Picture rolling a ball downhill until it settles at the bottom. That is all it is.

The same thing in code

python · from scratch, no library
# two houses: [size in 100 sqft, bedrooms] and the real price in lakhs
X = [[12, 2], [18, 3], [25, 4], [30, 4]]
y = [40, 62, 88, 101]

w1, w2, b = 0.0, 0.0, 0.0      # start knowing nothing
lr = 0.001                       # how big each nudge is

for step in range(10000):
    # 1. guess the price for every house
    preds = [w1*x[0] + w2*x[1] + b for x in X]

    # 2. how wrong were we, for each house
    errs  = [p - t for p, t in zip(preds, y)]

    # 3. nudge each number in the direction that reduces the error
    w1 -= lr * sum(e*x[0] for e, x in zip(errs, X)) / len(X)
    w2 -= lr * sum(e*x[1] for e, x in zip(errs, X)) / len(X)
    b  -= lr * sum(errs) / len(X)

print(w1, w2, b)
print("a 22-hundred-sqft 3BHK →", w1*22 + w2*3 + b)
The point of showing this

That is a real machine learning model, written in 12 lines, with no library at all. Guess, measure the mistake, nudge, repeat. Every model in this entire session works that way — including the one behind ChatGPT. Everything else is just more numbers and a cleverer shape.

The same thing with scikit-learn — 4 lines

python · scikit-learn
from sklearn.linear_model import LinearRegression

model = LinearRegression()
model.fit(X, y)                      # the whole loop above, done for you

print(model.coef_, model.intercept_) # your w1, w2 and b
print(model.predict([[22, 3]]))    # predict a new house

A full, real project — loan approval

python · the shape of every classical ML project
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report

# 1. load the table
df = pd.read_csv("loans.csv")

# 2. split into "the clues" and "the answer"
X = df[["income", "age", "job_years", "credit_score", "past_defaults"]]
y = df["approved"]

# 3. hide 20% of the rows so we can test honestly later
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2)

# 4. train
model = RandomForestClassifier(n_estimators=200)
model.fit(X_tr, y_tr)

# 5. check it on rows it has never seen
print(classification_report(y_te, model.predict(X_te)))

# 6. which clue mattered most? banks always ask this
for name, score in zip(X.columns, model.feature_importances_):
    print(name, round(score, 3))
The mistake everyone makes once

Never test your model on the same rows you trained it on. It will look brilliant and then fail completely in the real world. That is called overfitting — the model memorised the answers instead of learning the pattern, like a student who memorised last year's paper.

That is why line 3 above hides 20% of the data. Always.

Why scikit-learn is so pleasant

Every single model has the same three commands: .fit() to train, .predict() to use, .score() to check. Swapping a decision tree for a random forest is a one-word change. Learn the pattern once and you can use fifty models.

In price = w₁ × size + w₂ × bedrooms + b, what does training actually change?
w₁, w₂ and b. The data never changes, and the formula never changes. Training only hunts for the three numbers that make the predictions closest to reality. A 7 billion parameter model is exactly this, with 7 billion numbers instead of three.
03

Deep Learning

Stack simple maths in layers, feed it raw photos or raw text, and it works out for itself what to look at. Nobody tells it what a whisker is.

Why we needed it

Classical ML needs you to hand it good columns. That works fine for a loan table. Now try it on a photo.

What column would you write for "is there a cat in this picture"? Number of whiskers? Ear angle? You cannot. Nobody can. A photo is a million tiny colour dots and the meaning is buried in how they sit together.

So deep learning learns the columns itself. That is the entire reason it exists.

One neuron — the whole building block

output = activation( w₁x₁ + w₂x₂ + w₃x₃ + b )
Look familiar? It is linear regression, with one extra bend at the end

Multiply each input by a weight, add them up, add a bias. So far, identical to the house price formula. Then one new thing: pass it through an activation, which is just a little bend.

That bend matters enormously. Without it, stacking a hundred layers of straight lines gives you... one straight line. The bend is what lets the network learn curves, corners and complicated shapes.

SigmoidSquashes anything into 0 to 1Final layer, yes/no answers

Here is the beautiful part. Nobody programmed these layers, but if you look inside a trained image network you find:

  • Early layers found edges and simple colour patches
  • Middle layers combined those into corners, circles, textures
  • Later layers combined those into eyes, wheels, letters
  • The last layer combined those into "cat", "car", "the number 7"

It built its own ladder from dots to meaning. That is what "deep" means — many layers, each one seeing something slightly bigger than the last.

How it learns: forward, then backward

Show it a photo
→

→
Wrong. It was a cat
→
Work backwards:
whose fault was it?
→

a tiny bit
Repeat a few million times. That backward blame-sharing is called backpropagation

Same three steps as the house price model: guess, measure the mistake, nudge. The only new idea is that the mistake has to be shared backwards across every layer, so each of the millions of weights knows how much it was to blame.

PyTorch — the tool you will actually learn

PyTorch is the library almost all research and most industry uses now. It gives you three things: fast maths on a GPU, ready-made layers, and automatic mistake-sharing so you never do the backward maths by hand.

python · a complete network in PyTorch
import torch
import torch.nn as nn

# 1. describe the shape: 784 pixels in, 10 answers out
model = nn.Sequential(
    nn.Linear(784, 128),   # the w·x + b part
    nn.ReLU(),              # the bend
    nn.Linear(128, 64),
    nn.ReLU(),
    nn.Linear(64, 10)      # 10 digits, 0 to 9
)

# 2. how we measure being wrong, and how we nudge
loss_fn   = nn.CrossEntropyLoss()
optimiser = torch.optim.Adam(model.parameters(), lr=0.001)

# 3. the training loop — this is the whole of deep learning
for epoch in range(5):
    for images, labels in train_loader:

        guesses = model(images)              # forward: make a guess
        loss    = loss_fn(guesses, labels)   # how wrong were we

        optimiser.zero_grad()                # clear the old blame
        loss.backward()                      # backward: share the blame
        optimiser.step()                     # nudge every weight

    print("epoch", epoch, "loss", loss.item())
Read those three lines again

loss.backward() then optimiser.step(). That is the same "measure the mistake, then nudge" from the house price example. Only now it nudges a million weights at once, and PyTorch works out all the calculus for you.

Every deep learning script you ever read has this loop in it. Find the loop and you understand the file.

Use a model someone else already trained

python · transfer learning, the practical way
from torchvision import models
import torch.nn as nn

# ResNet already learned edges, shapes and textures from millions of photos
model = models.resnet18(weights="IMAGENET1K_V1")

# freeze everything it already knows
for p in model.parameters():
    p.requires_grad = False

# replace only the last layer with your own 3 categories
model.fc = nn.Linear(512, 3)   # healthy / diseased / unclear

# now train on just 200 of your own photos. This actually works.
This is how real projects get done

Almost nobody trains an image model from nothing. You take one that already learned to see, freeze it, and teach it your last step. You need a few hundred photos instead of a few million, and an afternoon instead of a month.

Why a GPU

Training is millions of the same small multiplication. A normal processor has a few strong cores and does them mostly one after another. A GPU has thousands of weak cores and does them all together.

A job that takes 3 weeks on a laptop takes about 6 hours on a decent GPU. That is the whole reason NVIDIA is worth what it is worth.

Why do we need the activation function, the little bend?
Straight lines stay straight. Adding straight lines together only ever gives you another straight line, so a hundred layers would be no better than one. The bend is what lets the network learn curves and complicated shapes. It is the single most important small detail in deep learning.

Generative AI

The job changed completely. You no longer collect data and train a model. Somebody else already trained it. Your job is now to aim it, feed it the right facts, and wire it into something useful.

Say this out loud once

In classical ML, the model is the product and you build it. In Gen AI, the model is a raw ingredient and you build the system around it. That is the whole shift, and it is why the job title changed.

RAG, because this is what you will build most

The problem: the model knows the internet, but it does not know your leave policy, your product catalogue, your contracts. And if you just ask, it will happily invent an answer.

Why turn text into numbers? Because then "how many holidays do I get" and "what is the annual leave allowance" end up close together as numbers, even though they share almost no words. That list of numbers is called an embedding, and finding the closest ones is what a vector database does.

python · a small but complete RAG
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_chroma import Chroma
from langchain_ollama import OllamaEmbeddings, ChatOllama

# 1. read the PDF and cut it into overlapping chunks
pages  = PyPDFLoader("hr_policy.pdf").load()
chunks = RecursiveCharacterTextSplitter(
             chunk_size=800, chunk_overlap=100).split_documents(pages)

# 2. turn every chunk into numbers and store them
db = Chroma.from_documents(chunks, OllamaEmbeddings(model="nomic-embed-text"))

# 3. a question comes in — fetch the closest chunks
question = "How many casual leaves do I get in a year?"
found    = db.similarity_search(question, k=4)
context  = "\n\n".join(d.page_content for d in found)

# 4. give the model the facts, and tell it not to guess
prompt = f"""Answer using ONLY the policy text below.
If the answer is not in it, say "not in the policy".

POLICY:
{context}

QUESTION: {question}"""

print(ChatOllama(model="mistral").invoke(prompt).content)
That single instruction is the whole trick

"Answer using ONLY the text below. If it is not there, say so." Without that line the model fills gaps with confident nonsense. With it, you get an honest "not in the policy". This one sentence is the difference between a demo and something a company can actually use.

Where Gen AI projects actually fail

It makes things up. Ground it in real documents and tell it to refuse when unsure.

Nobody measured anything. "It looked good in the demo" is not testing. Write 30 real questions with known answers and check them after every change.

The bill. A long prompt sent a million times a day costs real money. Watch the token counts from day one.

Slow. Five model calls chained together means five waits. Users leave.

The wrong tool entirely. If the answer lives in a database, write a SQL query. Not every problem needs an LLM.

Where the three fit together

Classical ML
Tables of numbers. Predict a number or a group. Cheap, fast, explainable. Still runs most of the industry.
Deep learning
Pictures, sound, signals. Learns what to look at by itself. Needs lots of data and a GPU.
Gen AI
Language and open questions. Somebody else trained it. You aim it, feed it facts, and wire it up.
Your company wants a bot that answers staff questions from 400 internal PDFs. What do you build?
RAG. Fine-tuning teaches a model a style, not facts, and every time a policy changes you would have to train again. RAG looks up the current document at the moment of the question, so updating a PDF updates the answer instantly. It also lets you show the user exactly which page the answer came from, which is usually what the business really wants.
05

The Timeline

From Turing in 1936 to AI agents today. Ninety years, and only about a dozen moments that really mattered.

The whole story, in order

This did not start in 2017. It started with one man asking whether a machine could think at all, nearly ninety years ago.

Part 1 · The foundations

1936
Turing invents the idea of a computer
Alan Turing describes an imaginary machine that reads instructions off a tape and follows them. No such machine existed yet. He was writing down, on paper, what a computer is. Everything we build today sits on this one idea.
1943
The first artificial neuron, on paper
McCulloch and Pitts write down a simple maths version of a brain cell: take some inputs, add them up, fire if the total is big enough. Still exactly what a neuron in PyTorch does today.
1945
Real computers get built
ENIAC, a room-sized machine of 18,000 valves. It took days to rewire it for a new job. But now the idea from 1936 actually existed in metal.
1950
Turing asks: can a machine learn?
In one famous paper Turing suggests something radical. Do not try to program an adult mind. Build something like a child's mind and teach it. That single sentence is the beginning of machine learning.
1956
The field gets its name
A summer meeting at Dartmouth College. A handful of researchers coin the phrase "artificial intelligence" and predict they will crack it in a few years. They were off by about seventy.
1957
The Perceptron — the first machine that learned
Frank Rosenblatt builds a real machine that adjusts its own weights from examples. Show it shapes, it gets better. Guess, measure the mistake, nudge. The same loop you saw in the house price example.
1969
The first AI winter
Minsky and Papert prove a single perceptron cannot even learn a basic either-or rule. Funding collapses. AI research goes quiet for years. The fix was already known — stack more layers — but nobody could train them yet.

Part 2 · Learning gets deep

1986
Backpropagation — the missing piece
Rumelhart, Hinton and Williams show how to share the blame backwards through many layers, so every weight learns from its own mistake. Now you can finally train a deep network. This is the loss.backward() line from the PyTorch slide.
1989
CNNs read handwriting
Yann LeCun builds a network that reads the digits on bank cheques, and it goes into real use. First proof that a neural network can do a real job at scale.
1997
LSTM, and Deep Blue beats Kasparov
LSTM gives networks a proper memory for sequences, and runs language tasks for the next twenty years. The same year, a chess computer beats the world champion — though by brute force, not by learning.
2006
"Deep learning" is reborn
Hinton shows a practical way to train networks with many layers, and gives the field a new name to shake off the old bad reputation. Quiet at the time. Enormous in hindsight.
2009
ImageNet — someone finally builds the data
Fei-Fei Li's team labels 14 million photos. The theory had been ready for twenty years. What was missing was enough examples to learn from.

Part 3 · The big bang

2012
AlexNet — the moment everything took off
A deep network wins the ImageNet contest by a huge margin, crushing every hand-built method. The trick was running it on gaming graphics cards. Old idea plus big data plus GPUs. Within two years, everyone had switched. This is the true start of the modern AI era.
2017
Attention Is All You Need — the transformer
Google throws away one-word-at-a-time reading. Now every word looks at every other word at the same time, so a whole sentence trains together instead of in a queue. Faster, better memory, and it scales. Every model in the rest of this session is a version of this paper.

Part 4 · The AI everyone now uses

2018
The design splits in two: BERT and GPT
Google takes one half (BERT) — reads both ways, great at understanding, ran Google Search for years. OpenAI takes the other half (GPT) — reads left to right and plays one simple game: guess the next word. The second one turned out to be the important one.
2020
GPT-3 — size turns into a surprise
175 billion numbers inside it. The shock was not that it wrote well. It was that you could show it three examples inside your message and it would copy the pattern, with no retraining at all. Prompt writing was born here.
2022
ChatGPT — manners, not a new design
No new architecture. They showed it good answers, let humans rank which reply was better, and trained it to give the better one. Suddenly it follows instructions instead of just continuing your sentence. In November it reaches the public, and the world notices.
2023
Open weights arrive
Meta gives Llama 2 away as a download, and Mistral 7B lands with a fully free licence, small enough for a laptop. Until now you could only rent AI. Now you can own a copy. The last slide of this session exists because of this year.
2025 →
Agents — the biggest shift since ChatGPT
Until now the model answered and stopped. Now it plans, uses tools, and works in a loop — read the ticket, search the docs, run the code, check the result, try again. Two things made it work: models that think for longer before answering, and giving them real tools to call.
The change in your job: you stop writing one clever prompt, and start designing what the model is allowed to do.
The pattern across ninety years

Look at what actually caused each jump. Almost never a brand new idea.

1957: the learning loop. 1986: a way to train many layers. 2012: enough data and fast enough chips. 2017: a shape that scales. 2022: manners. 2025: tools and time to think.

The neuron from 1943 and the learning loop from 1957 are still sitting inside everything. We mostly got better at feeding them.

Why the old way got stuck

Worth understanding what 2017 actually fixed. Before it, models read a sentence one word at a time, like reading with your finger, carrying a little memory along. Three problems:

  • Too slow. Word 50 had to wait for word 49. The computer just sat there waiting.
  • Bad memory. By word 200 it had almost forgotten word 1.
  • Squeezed too tight. The whole sentence got crushed into one small summary before the answer even began.

Attention fixed all three at once. That is why one paper mattered so much.

Encoder, decoder, or both

The 2017 design had two halves. Different models kept different halves. This is the most useful thing to remember.

TypeSeesTrained byGood atExamples
Encoder onlyThe whole sentence, both waysHide a word, guess itUnderstanding and sortingBERT
Decoder onlyOnly what came beforeGuess the next wordWriting anythingGPT, Llama, Mistral, Claude
Both halvesFull input, then writes outputText in, text outTranslating, summarisingT5, the original 2017 model
Why decoder-only won

"Guess the next word" needs nobody to label anything. Every sentence ever written on the internet is already a free practice question. And once a model is really good at it, almost any job can be written as text: translate this, summarise this, answer this, code this.

One simple game. Endless free practice. Every job. That is why almost everyone picked this half.

Four words to remember it by

2017 gave the design. 2020 gave the size. 2022 gave the manners. 2025 gave the tools. That is the modern era in four words.

Why is a transformer so much faster to train than the old word-by-word models?
Everything at once. The old model had to finish word 49 before starting word 50. Attention handles all the words together in one go, so the whole sentence goes through the machine at the same time.

Diffusion vs Autoregressive

Two very different ways to make something new. One is like writing a sentence, left to right. The other is like carving a statue out of a rough block of stone.

Autoregressive
One piece at a time, in order
  • Guesses the next word, using everything written so far
  • Adds that word, then guesses again
  • The answer appears left to right, word by word
  • Cannot go back and fix word 3 after writing word 40
  • Takes one step for every single word

Used by: GPT, Claude, Llama, Mistral, Gemini — all text models.

Diffusion
Start with noise, clean it up
  • Starts with a screen of pure static, like an old TV
  • Works out which bits are junk and rubs a little away
  • Does that 20 to 50 times. The picture gets clearer each round
  • The whole picture improves every round
  • Later rounds can fix mistakes from earlier rounds

Used by: Stable Diffusion, Midjourney, DALL·E, video models.

At every step the model gives a score to every word it knows — often more than 30,000 words. Then it picks one.

There is a dial called temperature for that pick. Turn it low and it always plays safe and boring. Turn it high and it takes risks and gets creative, sometimes silly.

How it learns: take a real photo, mess it up with a known amount of static, and ask the model to spot exactly what junk was added. Do that a billion times and it gets very good at removing junk.

How it draws: start with nothing but junk, and remove it over and over. A picture is left behind.

Your words steer it. The prompt is fed in at every round, so "a red car" quietly pushes every single round a bit more towards a red car.

Why the split happened

Text is discrete
A word is either "cat" or "dog". There is nothing in between. You cannot half-blur a word and still have a word. So you must pick one, then the next.
Images are continuous
A dot on screen can slide smoothly from grey to slightly lighter grey. Blurring and un-blurring makes perfect sense here.

Differences you will actually notice

The trick that made it fit on a laptop

Cleaning up a full-size picture dot by dot is far too slow. So the model does all the work on a shrunk-down version, about 8 times smaller on each side, and only blows it up to a real picture at the very last step.

That one shortcut is why you can make images on a normal computer instead of a data centre.

One honest note

The neat split is starting to blur. There are now text models that work the "clean up static" way, and picture models that work the "one bit at a time" way.

Learn the clean split first. It explains the last ten years. Just know the line is moving.

Why do you see ChatGPT type out its answer, but an AI image just appears all at once?
It is the order things get made. Every word the text model produces is done and can be shown straight away. The picture model keeps improving the whole canvas every round, so until the last round there is no finished piece to show you.

Open vs Closed Licences

The real question is not "is it free". It is: can you download it, change it, and sell something built with it?

It is three buckets, not two

Everyone says "open or closed". But there is a big middle group, and that is where most popular models actually sit.

Truly permissive
Download it, change it, sell it, share it. No limits, no conditions. Licence names: Apache 2.0 or MIT.

Mistral 7B, Qwen
Open weights, with strings
You get the model file, but with rules attached. Things like a limit on how many users you can have, and a list of things you must not build.

Llama, Gemma
Closed / API only
You never get the file. You rent it over the internet and agree to their rules.

GPT, Claude, Gemini
The thing almost everyone gets wrong

"You can download it" is not the same as "open source". Proper open source means you get everything you need to build the thing again yourself.

With almost every "open" AI model you only get the finished file. You do not get the data it learned from, or the code that trained it.

Think of a cake. They gave you the cake. Not the recipe, not the ingredients. You can eat it. You cannot bake another one.

What you actually receive

You getApache 2.0Llama-styleClosed API
The model file itselfYesYesNo
Run it on your own computerYesYesNo
Train it further yourselfYesYesSometimes, on their servers
Use it to make moneyYesYes, with rulesYes, if you pay
Share the file with othersYesYes, but you must credit themNo
The data it learned fromAlmost neverNoNo
The code that trained itAlmost neverNoNo
Must you keep their name on itNoOften yesFollow their brand rules
A list of banned usesNoneYesYes

The rules that catch people out

  • User limits. Some licences say: once your app has a huge number of users, come back and sign a separate deal. No problem for a small startup. A very big deal for a large company.
  • Keeping their name. Some say if you train on top of their model, your model must keep their name in it, and you must show a "built with" credit.
  • Banned uses. A list of things you promise not to build — spying, weapons, illegal content. This still applies even when the file sits on your own machine.
  • Who owns the output. Check who owns what the model writes for you. Usually you, but always check.
  • "Non-commercial" tags. Many models say research only. Fine for a class demo. Not allowed in anything you sell.
  • Rules travel. If someone trains on top of Llama, the Llama rules still apply to their version too, whatever they wrote on the page.
The one habit to build

Check the licence before you start building, not after.

It happens all the time: a team works for three months, then someone finally reads the tag a week before launch and the whole project has to be thrown away. The tag is right there on the page. It takes ten seconds.

How to choose for a real project

What you care about mostPickWhy
Data must stay in-houseDownloadable model, run it yourselfNothing ever leaves your building
Best possible qualityPaid APIThe very best models are still rental only
Huge steady usageDownloadable modelOne fixed machine cost beats paying per word
Small or on-and-off usagePaid APINo machine sitting idle burning money all night
Small team, nobody to run serversPaid APIRunning it yourself is a real full-time job
It must never change on youDownloadable modelYour copy stays the same forever. Rented ones get retired
Heavy custom trainingDownloadable modelFull control
No internet where it runsDownloadable modelRented models always need internet
The honest middle path

Most real teams use both. A small free model does the easy, high-volume jobs — sorting, tagging, pulling out details, first drafts. The expensive paid model handles the genuinely hard thinking. Cheap where you can, strong where you must.

You train on top of a free downloadable model and put it inside an app you sell. Whose rules apply?
The original rules follow you. Anything you build on top carries the same terms — user limits, naming rules, banned uses. This is exactly why you read the licence before you start, not after.

The HuggingFace Model Hub

One giant website where the whole world uploads AI models. Think YouTube, but for models instead of videos.

What is on it

  • Models — millions of them. Some are 50 MB. Some are 400 GB.
  • Datasets — piles of data people have shared for training and testing.
  • Spaces — little live demos you can click and try in your browser. Nothing to install.
  • Code tools — free Python libraries that download and run all of the above.
Why this slide matters

When you type ollama pull mistral later in this session, the file comes from here. Same for every other local AI tool. Ollama is just a friendly front door. HuggingFace is the actual warehouse.

What is on a model page

PartWhat it tells youWhat to check

The files you will see

FileWhat it is
model.safetensorsThe model, in the safe modern format. It holds numbers only, so it cannot run anything on your computer. Always prefer this one.
pytorch_model.binThe old format. It can hide code that runs the moment you open it. Be careful.
something.ggufA shrunk-down, single-file version. This is the one that runs on a laptop.
config.jsonThe settings sheet. How big the model is, how much text it can hold.
tokenizer.jsonThe rules for chopping your text into pieces the model understands.
index.jsonA map, for big models that are split across many files.
README.mdThe description page itself.

Those confusing file names, explained

You will see a long list of files with names like mistral-7b-instruct.Q4_K_M.gguf. The Q number is how much the model has been squashed down to save space. Lower number, smaller file, slightly worse answers.

  • Q8 — barely squashed. Almost as good as the original. Biggest file.
  • Q5_K_M — squashed a bit more. Still very good.
  • Q4_K_M — the one almost everyone picks. Half the memory, only a small quality drop.
  • Q3 or Q2 — squashed hard. You can tell the answers got worse. Only if you are really short on space.
Rule of thumb

Not sure? Take Q4_K_M. It is what nearly everyone ends up using, and it is what Ollama picks for you by default.

How to find the right model

With millions of models, how do you pick? Use the filters on the left of the models page, then read the page. That is it.

  • What job — writing text, understanding pictures, speech.
  • Licence — pick Apache 2.0 or MIT if you ever want to sell what you build.
  • Language — really matters for Hindi, Tamil, Kannada and so on. Check the page for which languages it actually learned.
  • Sort by trending or downloads — trending is what is new and exciting. Downloads is what is proven.
  • File type — pick GGUF if you want to run it on your own laptop.

Safety, in plain words

Anyone can upload here. Just like anyone can upload a video to YouTube.

An old .bin file can hide code that runs on your computer the second you open it. So: stick to safetensors files, stick to well-known companies, and never switch on the setting called trust_remote_code for a model you do not know. That setting lets a stranger's code run on your machine.

Try this yourself

Open two model pages side by side. One with a full description, a licence, test scores and safe files. One with a blank page, no licence and old files.

Now ask yourself: which one would you put inside a bank's app, and how would you explain that choice to your boss?

You find a model with 40 downloads, no licence, a blank description and one old .bin file. It claims to beat GPT-4. What do you do?
Skip it. Four warning signs at once: you cannot legally use it without a licence, nobody explained what it is, the file type can run code on your computer, and a huge claim with zero proof. And that last option makes things worse — that setting is exactly what lets a stranger's code run on your machine.

Running a Model Locally

The model file sits on your own laptop. Your laptop does the thinking. Nothing goes to the internet. Here is how to set it up, step by step.

What "local" actually means

You download the model file, like downloading a game. Your laptop opens it and does all the work itself. No account. No internet. No bill. Nothing you type ever leaves your computer.

Why local
The good bits
  • Private — medical records, contracts, your code, none of it goes anywhere
  • Free to use — asking a million questions costs the same as asking one
  • Works with no internet — a factory, a ship, a village clinic, a plane
  • No limits — use it all night if you want
  • It never changes — your copy stays exactly the same forever
  • You learn more — you can finally see and change every setting
Why not local
The honest downsides
  • Not as smart — a small local model is nowhere near ChatGPT or Claude
  • Big models will not fit — your laptop has limits
  • Slower — you will watch the words crawl out
  • You maintain it — updates and problems are your job now
  • Bad with long documents — small models get confused fast
  • Wasteful at work — a server sitting idle still costs money

Will it fit? The simple sum

A model has billions of little numbers inside it. How much memory it needs is just: how many numbers × how much space each one takes. Then add 1 to 2 GB for working room.

The demo, in order

Do these seven things

1. Run ollama list. Point at the 4.4 GB. The whole thing is sitting right there on the disk.

2. Run ollama run mistral and ask it something normal.

Before the demo

Download the model the night before. Ask it one throwaway question so it is already warmed up. Keep screenshots as a backup. And keep the tiny 1B model ready — if the laptop struggles, switch to it and make that the lesson.

You have a 16 GB laptop and you want to run the 70B model. What happens?
It will not fit. Do the sum: 70 billion numbers × 0.6 bytes each is about 40 GB. You have 16 GB. Even squashing it right down lands near 25 GB, and by then the answers are ruined anyway.
