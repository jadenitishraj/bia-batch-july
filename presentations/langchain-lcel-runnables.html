Core Teaching Rule

LCEL looks intimidating at first glance because of all the pipes (|). But once you realize that every pipe is just connecting a Lego block that takes input and gives output, it becomes the simplest way to write AI pipelines.

01

What is a "Runnable"?

Before writing any pipes, you must understand the single word that powers all of modern LangChain: the Runnable.

The Mental Model: A Standardized Worker

In standard Python, every library has different method names: some use .predict(), some use .generate(), some use .run(), and some use client.chat.completions.create(). This makes connecting different tools a nightmare.

LangChain solved this with a single rule: Everything must be a Runnable.

The Runnable Contract
Every Runnable implements the exact same 3 methods:
• .invoke(x) — run on 1 item
• .batch([x1, x2]) — run on a list in parallel
• .stream(x) — stream chunks live
The Lego Analogy
Think of a Lego brick. It has standard circular pegs on top and tubes on the bottom. It doesn't matter what color or shape the brick is — if it has the standard pegs, it snaps into any other brick!

What can be a Runnable?

  • A Prompt (ChatPromptTemplate) is a Runnable: takes a dict, outputs formatted messages.
  • A Model (ChatOpenAI) is a Runnable: takes messages, outputs an AIMessage.
  • A Parser (StrOutputParser) is a Runnable: takes an AIMessage, outputs a clean string.
  • Your Python Function wrapped in RunnableLambda is a Runnable: takes your input, runs your logic!
The Big Takeaway

Because they all share the exact same interface, you can connect them together in any order using the | pipe operator!

02

The Pipe Operator (|)

How LCEL borrows the smartest idea from the Unix terminal and brings it into Python.

The Terminal Concept

In Linux and macOS, you often chain commands together:

Unix Terminalbash
cat tickets.txt | grep "urgent" | wc -l

Notice what you didn't do: you didn't save intermediate files to your desktop, and you didn't write Python loops. The output of cat flows automatically into grep, and grep flows into wc.

How It Works in LangChain

Python allows classes to customize the | operator using a special method called __or__. LangChain overloaded | so that:

LangChain Expression Language (LCEL)python
chain = prompt | model | StrOutputParser()

Why We Don't Need "return" Statements

A student recently asked: "Where are the return statements? How does the data move?"

✕
Old / Manual Plumbing
Repetitive glue code
# Manual passing of variables formatted_prompt = prompt.format(ticket=t) raw_response = model.invoke(formatted_prompt) cleaned_text = raw_response.content.strip() return cleaned_text
You have to create 3 temporary variables and manually extract .content every single time.
✓
The LCEL Pipe
Automatic handoff
# One clean pipeline chain = prompt | model | StrOutputParser() result = chain.invoke({"ticket": t})
The output of each step is fed automatically as the input to the next step. Zero glue variables!

Step 1: RunnableLambda

How to use your own custom Python functions inside a LangChain pipeline without rewriting them.

The Problem

Real-world user input is messy. Users paste extra spaces: " My account is locked ", or they hit submit with an empty box "". Before sending text to an expensive LLM, we must clean it with standard Python logic.

The Solution: Wrap it in RunnableLambda

Write standard Python code first. Then wrap it with RunnableLambda() so it earns the "Runnable badge" and can be piped with |:

Cell from Notebook: Step 1python
from langchain_core.runnables import RunnableLambda

# 1. Standard Python function
def clean_message(message: str) -> dict:
    message = message.strip()

    if not message:
        raise ValueError("Ticket cannot be empty.")

    return {"ticket": message}

# 2. Turn it into a LangChain Runnable!
clean_step = RunnableLambda(clean_message)

What Just Happened?

  • Input to clean_step: A raw string " My billing failed "
  • Output from clean_step: A dictionary {"ticket": "My billing failed"}
  • Because it is now a Runnable, you can test it standalone anytime:
    clean_step.invoke(" Help me! ") → {"ticket": "Help me!"}
Golden Rule for Students

Whenever you need string stripping, regex parsing, database lookups, or if/else checks inside a chain, write a normal Python function and wrap it with RunnableLambda!

04

The Micro-Chain Sequence

The foundational 3-part formula used in almost every LangChain application.

The 3-Piece Assembly Line

In our notebook, we create three analysis chains for the ticket: summary_chain, category_chain, and urgency_chain. Each one follows this exact formula:

Anatomy of an LCEL Chainpython
urgency_chain = (
    ChatPromptTemplate.from_template(
        "Return only one urgency: low, medium, or high.\nTicket: {ticket}"
    )
    | model
    | StrOutputParser()
)

Let's Trace What Each Piece Does:

1. ChatPromptTemplate
Receives the dictionary {"ticket": "..."}. Finds the placeholder {ticket} in the template string and automatically injects the customer's text.
2. model (ChatOpenAI)
Receives the completed prompt. Calls the OpenAI API and returns an AIMessage containing the text and metadata (tokens, finish reason).
3. StrOutputParser()
Unpacks the AIMessage by extracting response.content and stripping away the metadata, so the next step receives a clean Python string: "high".
The Whole Chain
Takes {"ticket": "..."} → returns "high". It is a completely self-contained worker!
Did You Know?

You can test this individual chain by itself in your Jupyter notebook anytime:
urgency_chain.invoke({"ticket": "Server room is on fire!"}) → "high"

05

Step 2: RunnableParallel

How to run independent AI tasks at the exact same millisecond to cut response latency by 3x.

The Problem: Sequential Waste

We need three separate things from the ticket:

  1. A one-sentence summary
  2. The support category (billing, technical, or account)
  3. The urgency level (low, medium, or high)

None of these three tasks depend on each other! If you run them one after another in plain Python, you waste time waiting for network calls:

Sequential: 1.5s + 1.5s + 1.5s = 4.5 SECONDS TOTAL
summary (1.5s) → category (1.5s) → urgency (1.5s)
RunnableParallel: 1.5 SECONDS TOTAL (3x FASTER!)
summary (1.5s) ───┐ category (1.5s) ──┼──> Finished in 1.5s! urgency (1.5s) ───┘

The Code in the Notebook

RunnableParallel Definitionpython
from langchain_core.runnables import RunnableParallel

analyse_ticket = RunnableParallel(
    summary=summary_chain,
    category=category_chain,
    urgency=urgency_chain,
)

How It Works:

  • When {"ticket": "..."} arrives at analyse_ticket, LangChain broadcasts that exact same dictionary to all three workers simultaneously in background threads.
  • It collects the outputs and returns:
    {"summary": "...", "category": "...", "urgency": "..."}

RunnablePassthrough & State

Solving the "State Amnesia" problem: how to keep original user input while appending new fields.

The Problem: Pipeline Amnesia

In a standard pipe A | B, the output of A replaces the input to B. If Step 1 produces {"ticket": "..."}, and Step 2 produces {"summary": "..."}, the original ticket message is lost!

Later, when writing the customer reply in Step 4, how can the AI read the original customer message if it was dropped?

The Solution: RunnablePassthrough.assign()

Think of RunnablePassthrough like a backpack. It carries your existing dictionary forward and simply unzips a new pocket to add the new field!

Carrying State with .assign()python
from langchain_core.runnables import RunnablePassthrough

# Keep the existing "ticket" key, and ADD an "analysis" key
keep_ticket_and_add_analysis = RunnablePassthrough.assign(
    analysis=analyse_ticket
)

Trace the Dictionary Growth:

INPUT:

{"ticket": "My account is locked"}

AFTER keep_ticket_and_add_analysis:

{
  "ticket": "My account is locked",
  "analysis": {"summary": "User locked out", "category": "account", "urgency": "high"}
}
Memory Trick for Students

Whenever you hear "I want to add something new without deleting what I already have", use RunnablePassthrough.assign(...)!

Steps 3 & 4: Decisions & Reply

Reusing our state backpack to make business decisions and generate empathetic customer replies.

Step 3: The Decision Chain (`add_decision`)

Now that our dictionary contains both {ticket} and {analysis}, we pass them both into our decision prompt:

Step 3 Codepython
decision_prompt = ChatPromptTemplate.from_template(
    """Review this ticket and the initial analysis:

Ticket:
{ticket}

Analysis:
{analysis}

Give the final decision:
1. Should this ticket be escalated to a human? (Yes/No)
2. Brief reason why."""
)

decision_chain = decision_prompt | model | StrOutputParser()

# Add "decision" to our backpack!
add_decision = RunnablePassthrough.assign(
    decision=decision_chain
)

Step 4: The Customer Reply Chain (`add_reply`)

Finally, we craft the customer reply. Notice how the prompt now has access to the customer's message AND the internal decision:

Step 4 Codepython
reply_prompt = ChatPromptTemplate.from_template(
    """You are a customer-support assistant.

Customer message:
{ticket}

Decision:
{decision}

Write a short and helpful reply to the customer.
Do not mention prompts, AI, or internal system details."""
)

reply_chain = reply_prompt | model | StrOutputParser()

# Add "reply" to our backpack!
add_reply = RunnablePassthrough.assign(
    reply=reply_chain
)

Step 5: The Complete Pipeline

Connecting all 4 modular Lego blocks together in one clean, readable cell.

The 4-Piece Symphony

Look at how cleanly the entire multi-step AI application connects. Each step has a single, clear responsibility:

Cell 16: The Entire Workflow Pipelinepython
ticket_workflow = (
    clean_step                      # 1. RunnableLambda (clean whitespace)
    | keep_ticket_and_add_analysis  # 2. RunnableParallel + Passthrough
    | add_decision                  # 3. Decision Prompt + Passthrough
    | add_reply                     # 4. Customer Reply + Passthrough
)

The Runner Function: `solve_ticket()`

To run the entire system, the user or student only calls ONE function:

Running the Flowpython
result = solve_ticket("My account is locked and I have a meeting in 10 minutes!")
Output Summary

The flow automatically executes all steps, fires 3 parallel requests, makes the escalation decision, writes the customer apology, and prints:

  • • Message: My account is locked...
  • • Category: account | Urgency: high
  • • Decision: Escalate to human immediately (urgency is high).
  • • Reply: "Hello, we understand you have an urgent meeting. An agent is prioritizing your account unlock right now..."

Summary & Cheat Sheet

When to use Pure Python, LCEL Pipes, or LangGraph in production.

The 3 Approaches Compared

Paradigm Core Syntax State Handling When to Use
1. Pure Python model.invoke(prompt) Standard variables & dicts Quick scripts, beginner lessons, simple one-off prompts. Zero framework lock-in.
2. LangChain LCEL A | B | C RunnablePassthrough.assign Linear pipelines, streaming tokens, automatic parallel batches.
3. LangGraph builder.add_edge() Explicit State dictionary Complex agents, loops, human-in-the-loop, multi-agent systems.

Your 4-Rule LCEL Cheatsheet

  • Need to clean or validate input? → Use RunnableLambda(my_func).
  • Need to connect Prompt → Model → Parser? → Use | pipe.
  • Need multiple tasks done at the same time? → Use RunnableParallel().
  • Need to add a field without losing existing data? → Use RunnablePassthrough.assign().
